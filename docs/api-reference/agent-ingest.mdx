# Agent ingest

Use this guide when an agent, automation, or external service needs to send images into Pindeck from another system. The common path is:

1. Find a public image URL.
2. Build a stable `externalId` for deduplication.
3. Send the image to `/ingestExternal`.
4. Let Pindeck copy the file into RustFS, create the image record, extract colors, and put moderated sources into review.

## Endpoint

```text
POST {VITE_CONVEX_SITE_URL}/ingestExternal
Authorization: Bearer <INGEST_API_KEY>
Content-Type: application/json
```

Set `VITE_CONVEX_SITE_URL` in your local `.env.local` (git-ignored).

## Required fields

| Field | Description |
| --- | --- |
| `imageUrl` | Public URL that Pindeck can download and copy into RustFS. |
| `userId` | Pindeck user id that owns the imported image. |

## Recommended fields

| Field | Description |
| --- | --- |
| `sourceType` | Use `discord`, `pinterest`, `upload`, or `ai`. Moderated sources such as `discord` and `pinterest` enter review before publishing. |
| `externalId` | Stable idempotency key, such as `pinterest:<board-id>:<pin-id>` or `discord:<guild-id>:<message-id>:<attachment-id>`. |
| `sourceUrl` | Original page, pin, post, or message URL. |
| `title` | Human-readable title. |
| `description` | Short context for search and review. |
| `tags` | Array of searchable tags. |
| `category` | Broad classification, usually `General` when unknown. |
| `importBatchId` | Optional Convex import batch id, if the integration has already created one. Omit for simple external automations. |
| `sref` | Style reference id when the import came from an SREF workflow. |

## Minimal request

```bash
curl -X POST "${VITE_CONVEX_SITE_URL}/ingestExternal" \
  -H "Authorization: Bearer $INGEST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "USER_ID",
    "imageUrl": "<public HTTPS image URL>",
    "sourceType": "pinterest",
    "externalId": "pinterest:board-123:pin-456",
    "sourceUrl": "https://www.pinterest.com/pin/456",
    "title": "Imported reference",
    "tags": ["pinterest", "reference"]
  }'
```

Successful responses return the created `imageId` and resolved `userId`.

```json
{
  "imageId": "k17...",
  "userId": "j57..."
}
```

## JavaScript agent example

```ts
type PindeckIngestPayload = {
  userId: string;
  imageUrl: string;
  sourceType?: "discord" | "pinterest" | "upload" | "ai";
  externalId?: string;
  sourceUrl?: string;
  title?: string;
  description?: string;
  tags?: string[];
  category?: string;
  importBatchId?: string;
  sref?: string;
};

export async function sendToPindeck(payload: PindeckIngestPayload) {
  const base = process.env.VITE_CONVEX_SITE_URL;
  if (!base) throw new Error("Set VITE_CONVEX_SITE_URL");
  const response = await fetch(`${base.replace(/\/$/, "")}/ingestExternal`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.INGEST_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(payload),
  });

  if (!response.ok) {
    throw new Error(`Pindeck ingest failed: ${response.status} ${await response.text()}`);
  }

  return response.json() as Promise<{ imageId: string; userId: string }>;
}
```

## Moderated sources

Images with `sourceType` set to `discord` or `pinterest` are created as draft/moderated imports. They are available to the review workflow before becoming active in the main library.

For Discord-specific review tooling, use `/discordQueue` to list queued items and `/discordModerate` to approve, reject, or generate variations for a queued image.

For Pinterest, keep `sourceUrl` as the original pin/page URL, but still send a
downloadable `imageUrl`. Pindeck stores its own RustFS copy so Pinterest
references remain usable for boards, decks, color extraction, and AI variation
workflows even if the source URL changes later.

## Integration checklist

- Use `externalId` on every automated import.
- Keep `INGEST_API_KEY` server-side only.
- Omit `importBatchId` unless you have a real Convex import batch id.
- Send `sourceUrl` so reviewers can trace where an image came from.
- Prefer direct image URLs that do not require browser cookies.
- Retry `502` responses with backoff; they can mean the upstream image host or RustFS persistence step failed.

## Agent source (`sourceType: "agent"`)

Use this when an agent has already analyzed the image itself. Pindeck stores the agent's metadata as-is and runs **no** VLM, OpenRouter or palette extraction.

### Extra fields (honored only for `sourceType: "agent"`)

| Field | Description |
| --- | --- |
| `colors` | Array of `#rrggbb` hex values (max 12, normalized and deduped). These are also added to `tags`. |
| `group`, `genre`, `style`, `shot` | Same facets the VLM normally fills, for example `Film`, `Action`, `Digital`, `Wide Shot`. |

For other source types, `colors`, `group`, `genre`, `style` and `shot` are ignored.

### Lifecycle

1. `/ingestExternal` creates the row with `status: "draft"` and `aiStatus: "completed"`.
2. Media is copied to RustFS by the `pindeck-external-ingest` task (or inline when orchestration is off). That creates the derivatives/thumbnails. The agent palette is **preserved**: no resampling, and no overwrite from the gateway's colors.
3. The item appears in **Upload → Agent**, pre-filled like a Local Upload result. Title and description are editable there.
4. **Approve** calls `finalizeUploads`, which only flips `draft → active`. No analysis, palette, variation or notification jobs run. **Discard** deletes the draft.

### Example

```json
{
  "userId": "USER_ID",
  "imageUrl": "<public HTTPS image URL>",
  "sourceType": "agent",
  "source": "Midjourney",
  "externalId": "midjourney:<jobId>:<index>",
  "sourceUrl": "https://www.midjourney.com/jobs/<jobId>?index=<index>",
  "title": "Samurai in burning wasteland",
  "description": "Armored samurai stands amid fire and smoke on a scorched plain.",
  "tags": ["samurai", "fire", "wide shot", "monochrome yellow", "sref-779163157"],
  "category": "Film",
  "sref": "779163157",
  "colors": ["#9d894e", "#aea063", "#19150e", "#63512d", "#e9d038"],
  "group": "Film", "genre": "Action", "style": "Digital", "shot": "Wide Shot"
}
```

## Operator notes

Reference credentials **by variable name only**. Never paste values into docs, PRs, skills or new files.

| Purpose | Primary (Bitwarden Secrets Manager) | Fallback (local pindeck repo `.env` / `.env.local`) |
| --- | --- | --- |
| Bearer key | `PROXMOX_HOME_HOSTINGER_DISCORD_BOT_PRIVATE_INGEST_API_KEY` | `INGEST_API_KEY` |
| Target `userId` | `PROXMOX_HOME_PINDECK_PRIMARY_DISCORD_INGEST_OWNER_CONVEX_USER_ID` | `PINDECK_USER_ID` |
| Convex site URL | `PINDECK_CONVEX_SITE_URL` | `VITE_CONVEX_SITE_URL` |
| Public image hosting | `MEDIA_GATEWAY_URL`, `MEDIA_GATEWAY_TOKEN` | same names |

- **Backticks in BWS values.** Some BWS values are stored wrapped in backticks. Trim them before use, because a wrapped `userId` fails the `v.id("users")` validator with a 500.
- **Public image URL.** `imageUrl` must be publicly fetchable. To ingest local files, first upload them with `POST {MEDIA_GATEWAY_URL}/upload` (multipart `userId`, `folder`, `file`; Bearer `MEDIA_GATEWAY_TOKEN`), then send the returned `publicUrl`.

### VLM behavior by `sourceType`

| `sourceType` | Initial row | Analysis |
| --- | --- | --- |
| `upload`, `ai`, or omitted | `active` | VLM + palette run immediately. |
| `discord`, `pinterest` | `pending`, `aiStatus: queued` | Skipped at ingest; runs on approval. |
| `agent` | `draft`, `aiStatus: completed` | Never. The agent metadata is final. |

Re-posting the same `externalId` returns `duplicate: true`. Note that `/discordQueue` lists Discord-lineage items only.
